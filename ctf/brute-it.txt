Brute It

   Lien de la machine

   Dans ce test, j'ai pour biut de trouver des failles de sécurité sur une
   machine et d'essayer d'arriver à prendre le contrôle total de la
   machine : être en utilisateur root. Le thème de la machine est le
   bruteforce, c'est principalement dans le bruteforce

   utilisation de la commande nmap dans un premier temps on fait en sorte
   de découvrir les différents ports qui sont ouverts :
nmap -sC -sV 10.10.173.206
nmap -sC -sV 10.10.173.206

   f1754fc999430d8113c12071f37c29c3.png

   Sachant que l'on est sur un site web sur une machine challenge, je fais
   en sorte de regarder les différents onglets que l'on peut trouver sur
   le site en bruteforce en utilisant l'utilitaire gobuster :
gobuster dir -u http://10.10.173.206 -w /usr/share/wordlists/dirb/common.txt
gobuster dir -u http://10.10.173.206 -w /usr/share/wordlists/dirb/common.txt

   On énumère ensuite le site web et on trouve un onglet :
   6d51866963fcb219ed0cef8045ad374c.png

   Ensuite, on tombe sur une page donnant sur un formulaire de login. On
   trouve dans les commentaires du code source que l'on a un utilisateurs
   nommé admin et une personne nommée "john".

   Il faut donc utiliser le proxy de la suite burp pour trouver la manière
   que l'on doit utiliser pour bruteforce le site (quels arguments pour le
   login et le mot de passe). J'intercepte simplement la requête effectuée
   sur le serveur afin de récupérer les éléments que l'on doit utiliser
   pour bruteforce la page de login :
   e0c48ec7a8421a40e9791b08b93979dc.png

     ici j'ai simplement essayé avec le login admin et le mot de passe
     test pour voir quelles informations étaient utilisées.

   donc maintenant on sait quoi utiliser dans la commande hydra.
hydra -l admin -P /usr/share/wordlists/rockyou.txt 10.10.173.206 http-post-form
"/admin/:user=^USER^&pass=^PASS^:Username or password invalid"
hydra -l admin -P /usr/share/wordlists/rockyou.txt 10.10.173.206 http-post-form
"/admin/:user=^USER^&pass=^PASS^:Username or password invalid"

   Ici on spécifie que l'on doit utiliser un login et un password? Pour le
   password, on doit utiliser la liste de mot et on sait que le login est
   admin (récupéré en commentaire dans la page du formulaire), ensuite, on
   dit simplement à hydra où est ce qu'il doit les mettre dans la requête.
   On met le username dans le ^USER et le password dans le ^PASS. Ensuite,
   on définit le message qui apparaît lorsque notre couple login / mot de
   passe est incorect, ici Username or password invalid

   Sachant que l'on doit craquer la clé, on va utiliser john the ripper,
   donc il faut qu'on mette la clé dans un format spécifique que
   l'utilitaire john sait utiliser. Pour cela, j'utilisa la commande
   ssh2john

     Car c'est une clé privée SSH, d'où le ssh2john.

ssh2john key.rsa> key.txt
ssh2john key.rsa> key.txt

   maintenant on a ce qu'il faut pour craquer la clé.
john RSAkey.txt --wordlist=/usr/share/wordlists/rockyou.txt
john RSAkey.txt --wordlist=/usr/share/wordlists/rockyou.txt

   On trouve alors la passphrase protégeant la clé ssh :
   91f19106a6060a2ec3641f32d1157bfc.png

   On peut maintenant essayer de se connecter en ssh en utilisant
   l'utilisateur john et la clé :
   clé où on a bien sûr modifié les permissions (sinon SSH refuse de se
   connecter sur l'hôte distant) :
   chmod 600 key.rsa

   puis on utilise l'option -i afin de dire que l'on utilise une clé SSH
   pour se connecter.

   ssh -i key.rsa john@10.10.170.206
   On pense bien à utiliser la clé au format de base et pas celui de john

   On nous demande le mot de passe de la clé que l'on renseigne et on
   arrive à se connecter.
